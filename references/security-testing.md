# 安全测试（Security Testing）

> 对应用/接口做安全验证，聚焦 OWASP API Security Top 10 与常见漏洞：注入、越权（BOLA/BFLA）、鉴权缺陷、过量请求、输入注入。以「攻击者视角」构造用例，输出风险报告。

## 何时使用

- 用户说「安全测试这个接口」「测越权」「注入测试」「上线前安全自查」
- 需验证鉴权/授权模型、输入处理、速率限制是否到位

## 检查清单（OWASP API Top 10 映射）

1. **BOLA 越权对象**：用 A 的 token 访问/修改 B 的资源 ID → 应 403。
2. **BFLA 越权功能**：普通用户调用管理员接口 → 应 403。
3. **注入**：SQL/NoSQL/命令注入 payload 作入参 → 应被拦截或转义。
   ```
   ' OR '1'='1
   {"$gt": ""}
   ; cat /etc/passwd
   ```
4. **鉴权失效**：无 token / 过期 token / 篡改签名 → 应 401/拒绝。
5. **过量请求（速率限制）**：高频请求应触发 429。
6. **安全配置错误**：暴露堆栈/版本/调试端点 → 应隐藏。
7. **库存泄露**：响应包含多余敏感字段（密码、token、SSN）→ 应裁剪。
8. **未受限资源消耗**：超大 payload / 深分页 → 应限流或拒绝。
9. **SSRF**：让服务端请求内网/元数据地址 → 应被禁。
10. **批量分配**：多传未授权字段（如 `isAdmin`）→ 应忽略。

## 构造方法

- 复用 `scripts/test_matrix.py` 生成「安全」列，再补越权/注入专项用例。
- 对鉴权用多组身份 token 交叉验证（自己/他人/匿名/越权角色）。
- 注入用等价类：SQL、NoSQL、命令、LDAP、XSS 反射。

## 断言与报告

- 失败判定：未拦截 = 漏洞；错误体泄露敏感信息 = 配置缺陷。
- 输出风险报告（见 `references/reporting.md`）：按严重级（高/中/低）列证据与修复建议。
- **只测试你有权测试的系统**，不要对无授权目标做安全扫描。

## 与 API 测试关系

- API 测试关注「功能正确」，本 playbook 关注「被滥用时是否失守」。
- 二者共用请求构造能力，但安全测试以恶意/越权输入为主。

## 限制

- 不等于完整渗透测试；深度漏洞（逻辑漏洞、链式利用）需专业安全团队。
- 不替代依赖扫描（SCA）/DAST 工具，仅做接口层的攻击面验证。
